## 3. 对模型的修正点

### 3.1 已写进 params.json（只加 S 证据，数值都没动）
- `rebuild.lockRouteFromRound = 9`：commit@9 是 8 个 arm 里唯一赢过的，也是 R10 起 LP 最健康的一组 → 加 S 证据「方向性支持」。**没改数值**：样本只测了 9 这一个锁定回合，没有对照值；而且同一个 arm 里还开了 MERGE_BONUS/MAX_PAIRS/BENCH_BUDGET，没法单独归因。
- `advisor.levelPolicy`：卡 L4 / 慢升级都是 0/3，复现 MODEL-SPEC §3.3 引用的 REPORT §7「单改升级节奏无效」→ 加 S 证据。**没改数值**：样本调的是 bot 的 LEVEL_TARGET，不是 advisor 的 routeCaps / bossPhaseLevelFloor。

### 3.2 方向性观察（只写在这里，不写进参数）
- 卡 L4 会让后期断档：R13 只剩 3 人 → 支持 `bossPhaseLevelFloor = 6`（R10 后要满本），但没有直接测这个值。
- 慢升级（前期省、R12 只到 L5）中期 LP 更高，但 R14 仍 0 胜 → 「前期少升」可能有益，「后期不满本」有害；两者混在同一个 arm 里，需要拆开测。
- MAX_REFRESHES 16→28 输出逐字不变 → 【推断】默认 bot 根本没用到 16 次刷新上限（被金币或其他条件先卡住），这个开关在当前策略下不起作用。
- 激进凑对：前期减员变少，后期减员变多 → 和 commit@9 的差别可能在「锁本家」而不在「凑对」本身。

### 3.3 样本不足，暂不改
- `advisor.scoreSlot.*`（wCopy*/penOffBond 等）：bot 的 MERGE_HIT/PAIR_HIT 和顾问评分的量纲不同，也没有单独对照。
- `advisor.buyThreshold`、`advisor.levelPolicy.fundsBufferForLevel`、`advisor.levelPolicy.routeCaps`、`bossPhaseLevelFloor`：没有样本直接测。
- `rebuild.targets` / `bossWinTargets` / `minElitesForBoss` / `minLpForBoss`：样本没输出精锐/装备/层数。
- `advisor.pivot.*`、`rebuild.sellNonRouteFromRound`、`maxBoardRoutes`：没有测。
- `engine.*` / `channels.*` / `bosses.*`：都是引擎系数，样本不涉及。
- MODEL-SPEC §5 链 C 的预测「胜率 0.40-0.65」：那是 solo / 30 种子 / 顾问策略，本批是 coop / 3 种子 / bot 开关，不能拿来对照。

## 4. 下一批样本建议
1. 拆开 commit@9：只开 COMMIT=1 COMMIT_FROM=9（其余默认）vs 只开 MERGE_BONUS=120 MAX_PAIRS=10 BENCH_BUDGET=12，seeds ≥6。
2. 锁定回合扫描：COMMIT_FROM ∈ {7, 9, 11}，把其他开关固定成 commit@9 的组合，用来校准 `lockRouteFromRound`。
3. 升级节奏拆分：前期慢、R12 起追 L6（如 [1,1,1,2,2,2,3,3,3,4,4,5,6,6,6,6]）vs 基线，用来检验 `bossPhaseLevelFloor=6`。
4. commit@9 + 慢升级组合，seeds ≥6。
5. 换种子组（seeds 4..9 或更多）复测 commit@9，先确认 1/3 不是某一个种子偶然赢下来的（样本只有汇总行，看不出是哪个种子赢的）。

## 7. 归因结论

**无干净信号，不改数值。** 本轮 params.json 的数值一处没动，只在 `_evidence` 里追加了 3 条 S 证据，内容都是「数值不变」。

- 单变量对照（A 只开 COMMIT、C 只开 PAIR+BUDGET、level6-push 只改 LEVEL_TARGET）全是 0 胜场差，没有可以拿来改数的信号。
- 唯一的胜场出在 D（7 个开关全开），属于多开关同时开，按规则只能记方向；换种子组 4..9 后 0/6 对 0/6，方向性也不成立，所以把上一轮 `lockRouteFromRound` 的「方向性支持」**降级为噪声**。
- commit-split 报告里写的「COMMIT 锁定 + 凑对扩张协同产生组合效应」只有 1 个胜场撑着，而且 reseed 没复现，**不采纳**。
- level6-push：这个表和 bot 默认表 [1,1,1,2,2,3,3,4,4,4,5,5,6,6,6,6] 从 index 12 起都是 L6，真正改的是中期升得更慢（index 4/6/9/11），所以测的**不是** `bossPhaseLevelFloor`。方向上「中期慢升」能让 R9–R12 的 LP 更高（R11 19.3 vs 13.6）、R14 多活 2 人，但胜率不变。这和上一轮「慢升级」的观察一致，可以记作方向：**中期省钱改善道中存活，不改善 BOSS 胜率**。
- 写进 `_evidence` 的条目：
  - `rebuild.lockRouteFromRound` ← commit-split.md、commit-reseed.md（值 9 不变）
  - `advisor.levelPolicy` ← level6-push.md（数值不变）

## 8. 仍不敢改的项

- `rebuild.lockRouteFromRound = 9`：只测过 FROM=9 一个值，单开 COMMIT 没有效果，全开也复现不了 → 既没有对照值，也没有信号。
- `advisor.levelPolicy.*`（routeCaps / bossPhaseLevelFloor / fundsBufferForLevel）：三轮改 bot LEVEL_TARGET 都是 0 胜场差，而且测的是 bot 不是 advisor。
- `advisor.scoreSlot.*`（wCopy* 等）：MERGE_BONUS/MAX_PAIRS/BENCH_BUDGET 是 bot 量纲，单开 0 胜场差。
- `rebuild.targets` / `bossWinTargets` / `minElitesForBoss` / `minLpForBoss`：样本仍然没输出精锐/装备/层数。
- `engine.*` / `channels.*` / `bosses.*`：引擎系数，样本不涉及。
- 根本限制：baseline 在所有种子组里都是 0 胜，coop ABYSS 下 bot 的胜率地板太低。5–6 个种子在 0% 附近分辨不出 ±20pp 以内的差别。

## 9. 下一批样本建议

1. 让 matchrun 输出**逐种子**胜负（或者对 seeds 1..5 单种子各跑一次 D），先确定 D 的那一胜是哪个种子，再在这个种子上做开关消融。
2. commit@9 全开 vs baseline 加到 seeds ≥20（如 1..20），确认是否真的 >0。
3. 把评测换到区分度更高的场景（solo 或 `--lp 60`、`balance.mjs --boss-only`），先让 baseline 离开 0% 地板，再做单变量对照。
4. 跑 `lab/inspect.mjs` 输出逐回合精锐/装备/层数，对照 `rebuild.targets`。
5. COMMIT_FROM 扫描（7/9/11）放到第 2–3 条有信号之后再做，现在做只会全是 0/N。

## 第二轮采样（同日，换种子组复核）— 结论：上一轮的「commit@9 = 1/3」是种子运气，不是信号

| 样本 | arm | seeds | 胜 | 备注 |
|---|---|---|---|---|
| commit-split.md | A 只开 COMMIT 组 | 1..5 | 0/5 | avg 11.60 回合 |
| commit-split.md | B 只开 MERGE+PAIR+BUDGET | 1..5 | 0/5 | 数字与 A、C 完全一致（同一批种子跑出同一分布） |
| commit-split.md | C 只开 MAX_PAIRS+BUDGET | 1..5 | 0/5 | 同上 |
| commit-split.md | D 全开 commit@9 | 1..5 | **1/5** | 唯一赢的一组 |
| commit-reseed.md | D 全开 commit@9 | **4..9** | **0/6** | 换种子组即归零 |
| level6-push.md | R12 起追 L6 | 1..5 | 0/5 | R14 LP 0，末期追 L6 没救回来 |

**归因**：把 7 个开关拆开单跑（A/B/C）全部 0/5，只有全开时 1/5；同一组配置换种子组（4..9）后 0/6。
这两条合起来说明：那个唯一的胜场是**某一个种子下的偶然**，不是某个开关的因果效应。因此：

- **不改 params.json 的任何数值**（没有任何干净的单变量对照支持改动）。
- 现有参数表继续保持「无 bot 层可复现信号」的状态。

**这意味着什么**：ABYSS 的 0% 不是「调 bot 开关」能修的。三个结构性卡点仍然成立（见 MODEL-SPEC）：
R14 击杀窗口内 DPS 需求 18k–42k，而路线通道系数决定物理路线只有 0.02–0.67；破甲线 A>DEF/0.95 在 T5/T6 精锐基础 ATK 中位 577 下过不了 boss_1/2/6。
胜率要动，必须在**通道/破甲/终端集中**这三件事上改，而不是在 bot 的买卖节奏上改。

**下一批该跑的样本（优先级）**：
1. 单通道专精：把 4 个 bot 座位固定成同一条法系路线（炎/维多利亚），看团队通道是否叠加 —— 这直接检验「多人局合通道」假设。
2. 终端集中度：只给「最高 ATK 的单位」装备 vs 平均撒装备，seeds ≥6（这是顾问已经在用的假设，需要验证）。
3. 6 人档 vs 9 人档的收益差：固定 6 人满 vs 硬冲 9 人，seeds ≥6。
