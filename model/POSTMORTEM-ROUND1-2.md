# 复盘：为什么两轮样本「什么都没测出来」

写这份东西的原因很直白：我们跑了两轮、8 个 arm、约 40 局对局（约 1.5 小时机器时间），结论却是「没有可复现信号」。
如果就停在这里，等于白跑。下面是把「白跑」翻译成「下次不白跑」的账。

## 1. 事实清单

| arm | seeds | 胜 | 备注 |
|---|---|---|---|
| baseline | 3 | 0/3 | 另有一次 6 seeds 的 0/6 |
| commit@9（7 个开关全开） | 5 | 1/5 | 唯一赢过一次 |
| commit@9（换种子组 4..9） | 6 | **0/6** | 同一配置换种子即归零 |
| 只开 COMMIT 组 / 只开 MERGE 组 / 只开 PAIRS 组 | 各 5 | 0/5 / 0/5 / 0/5 | 三组的回合分布完全相同（11.60 / min9 / max13） |
| 卡 L4 | 3 | 0/3 | |
| 慢升级 | 3 | 0/3 | |
| MAX_REFRESHES=28 | 3 | 0/3 | 输出与 baseline 逐字节相同 |
| 激进凑对（90/24/8/10） | 3 | 0/3 | |
| R12 起追 L6 | 5 | 0/5 | R14 时 LP 0 |

## 2. 三个设计错误（这才是「为什么什么都没测出来」）

### 2.1 样本量根本不够，而我们把「测不出」当成了「没效果」

这是最致命的一条。用胜率做二值指标时，n 个种子全输的概率（真有效果 = 20% 的前提下）：

| n | 真 20% 效果时，全输（漏检）概率 |
|---|---|
| 3 | **51%** |
| 5 | 33% |
| 6 | **26%** |
| 10 | 10.7% |
| 20 | 1.2% |

也就是说：**我们所有 3 种子、5 种子的 arm，即使真有 20% 的胜率提升，也有一半/三分之一的概率被判成「没效果」。**
反过来看 95% 置信区间：0/3 对应的胜率上界是 **56%**。用 n=3 去否定一个 20% 的效应，在统计上是不成立的。

正确结论应该是：**8 个 arm 全部「未能分辨」，而不是「全部无效」。** 上一轮报告里写的「卡 L4/慢升级/刷新上限 都是 0/3，再次说明单改升级节奏无效」——这句话超出了数据能支持的范围。

### 2.2 指标选错了：用「赢没赢」当因变量

ABYSS 的胜率接近 0，二值输赢的信息量极低（40 局里只有 1 次赢）。而我们其实有大量**连续**、低成本、高信息量的指标：

- R13/R14 团队 LP（漏怪总量）
- BOSS 被打掉的血量百分比（`boss 2789572/3000000` —— 这是从 0% 到 7% 的直接量化）
- R12 起的每回合漏怪数、精锐数、装备数、层数

用连续指标，n=3 就能看出「伤害从 7% 提到 9%」这种小位移；用二值输赢，n=30 才勉强。

### 2.3 归因不干净，而且没有「开关真的生效」的体检

`commit@9` 一次开了 7 个开关；拆开单跑的三组回合分布一模一样（11.60/min9/max13），既可能真是巧合，也可能是**部分 env 没有生效**。
我们从来没做过一个「极端值必须改变行为」的体检（例如把 `SP_LAB_MAX_REFRESHES=0`，如果输出与 baseline 相同，就说明这个开关根本没接上）。没有这道体检，后面所有归因都建立在沙子上。

## 3. 结论：这轮真正学到的东西

1. **bot 层的开关不是瓶颈**。连续指标也印证：所有 arm 的 R13 LP、回合分布、BOSS 血量都没有系统位移。所以「调买卖节奏/升级节奏来把 0% 推上去」这条路径，在现有 bot 结构下大概率是死路——原因见 MODEL-SPEC：R14 需求 DPS 18k–42k，物理通道 0.02–0.67，破甲线过不了。
2. **要动的是结构，不是参数**：通道（法系/奥术）、破甲（精准/ATK 门槛）、终端集中（装备只喂一个 C）。
3. **测量系统本身要重做**，否则第三轮还是白跑。

## 4. 第三轮的设计（先定测量，再定假设）

**测量协议（必须满足）**
- 主指标：`R14 结束时 BOSS 被打掉的血量百分比`（连续），次指标：R13 团队 LP、R12+ 每回合漏怪。
- 每个 arm **≥20 seeds**（检测 20% 效果、漏检 <1.2%），或先用 n=5 做连续指标的粗筛，只把「连续指标有位移」的假设推进到大样本。
- **开关体检**：第一件事是跑一组极端值（`MAX_REFRESHES=0` / `MERGE_HIT=9999`），确认输出必须与 baseline 不同；不不同就说明开关没接上，先修接线。
- 每次 arm 必须**单变量**；多开关只允许出现在「组合验证」阶段。

**假设排序（按对结果的杠杆）**
1. 四人同法系路线 → 团队通道是否叠加（S 级：直接决定能不能杀 BOSS）
2. 终端集中 vs 平均撒装备（S 级：顾问当前假设，未验证）
3. 6 人档 vs 硬冲 9 人（A 级：9 人档理论收益大但概率低，见 NUMBERS §11）
4. 精准 3 人档（30% 防御穿透）在 boss_6 半血 DEF 2060 时的实际收益（A 级）

**失败判定**：如果 n=20、单变量、连续指标下仍无位移，就接受「bot 结构上限」的结论，把精力全部转到**顾问侧的人机接口**（人类自己当策略层），而不是继续在 bot 参数上耗机器时间。
